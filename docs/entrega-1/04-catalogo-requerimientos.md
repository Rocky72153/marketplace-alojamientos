# 4. Catálogo de requerimientos y reglas del negocio

**Fuente primaria:** guía oficial del proyecto Marketplace Alojamientos, secciones 5 y 6.  
**Estado:** especificación inicial derivada del enunciado y del análisis documental; requiere revisión y validación con los actores antes de comprometerse como alcance de desarrollo.

## 4.0 Levantamiento y procedencia

El levantamiento documentado se realizó mediante análisis de la guía oficial del proyecto (secciones 5 y 6) y triangulación con los objetivos de negocio, historias, casos de uso, criterios de aceptación, casos de prueba y matriz de trazabilidad de este repositorio. No hay evidencia de entrevistas, talleres u observaciones con clientes o usuarios; por tanto, no se presentan como actividades realizadas. Las propuestas derivadas del equipo quedan identificadas como tales y pendientes de validación por el PO, el equipo y el interesado de negocio.

La columna «Fuente de levantamiento» identifica la guía y los artefactos del proyecto relacionados con cada RF. La prioridad clasifica el alcance propuesto para Entrega 1 y no indica que la función esté implementada.

## 4.3 Reglas de negocio

| ID | Regla | Interpretación verificable |
|---|---|---|
| RN-001 | Cada publicación pertenece a un único anfitrión. | El sistema debe cumplir esta regla verificable: La publicación guarda un anfitrión; no se acepta propietario ambiguo. |
| RN-002 | Solo anfitrión crea; dueño o administrador puede modificar. | El sistema debe cumplir esta regla verificable: Autorización se valida en backend, no solo en interfaz. |
| RN-003 | Estados: BORRADOR, PENDIENTE_REVISION, ACTIVA, PAUSADA y BLOQUEADA. | El sistema debe cumplir esta regla verificable: Transiciones de estado se implementan y auditan. |
| RN-004 | Solo publicaciones activas aparecen en búsquedas y reciben reservas. | El sistema debe cumplir esta regla verificable: Búsqueda y confirmación filtran/validan estado activo. |
| RN-005 | La publicación debe tener datos mínimos antes de activarse. | El sistema debe cumplir esta regla verificable: Validación de título, descripción, ubicación, tipo, capacidad, precio, servicios/reglas e imágenes según implementación. |
| RN-006 | Capacidad > 0 y precio por noche > 0. | El sistema debe cumplir esta regla verificable: Rechazar valores cero/negativos. |
| RN-007 | Fecha de salida posterior a fecha de llegada. | El sistema debe cumplir esta regla verificable: Rechazar rangos vacíos/invertidos. |
| RN-008 | No se confirman reservas superpuestas para un alojamiento. | El sistema debe cumplir esta regla verificable: Revalidar al confirmar con control transaccional adecuado. Intervalos modelados como llegada incluida y salida excluida. |
| RN-009 | El total se compone de precio base, limpieza, servicio y cargos por adicionales; porcentajes configurables. | El sistema debe cumplir esta regla verificable: Guardar desglose/versionar componentes usados para que la reserva conserve el cálculo aceptado. La fórmula exacta de descuentos/extras debe documentarse en la política de cotización. |
| RN-010 | La reserva puede ser inmediata o requerir aprobación según configuración. | El sistema debe cumplir esta regla verificable: La guía también define la reserva inmediata como modelo obligatorio del MVP; propuesta: entregar reserva inmediata y dejar aprobación como extensión configurable, salvo decisión explícita del equipo. |
| RN-011 | Al menos una política de cancelación asociada a la publicación. | El sistema debe cumplir esta regla verificable: El cálculo consulta la política vigente ligada a la publicación; política concreta debe acordarse. |
| RN-012 | Cancelación registra usuario, fecha, motivo, devolución aplicable y estado final. | El sistema debe cumplir esta regla verificable: Los campos no pueden omitirse en la operación aceptada. |
| RN-013 | Reserva idempotente o mecanismo equivalente contra duplicados. | El sistema debe cumplir esta regla verificable: Un reintento lógico no crea reserva adicional. |
| RN-014 | Bloqueo administrativo conserva reservas futuras para auditoría y las pasa a revisión manual. | El sistema debe cumplir esta regla verificable: No borrar/cancelar silenciosamente las reservas futuras al bloquear el anuncio. |
| RN-015 | Acción de seguridad o cambio de estado relevante deja registro trazable. | El sistema debe cumplir esta regla verificable: Registro consultable de quién, qué, cuándo y resultado. |
| RN-016 | Pagos no reales; usar servicio en modo de pruebas para simular pagos. | El sistema debe cumplir esta regla verificable: No cobrar ni usar credenciales de producción. |
| RN-017 | Solo huésped con reserva completada para ese alojamiento puede reseñar/calificar. | El sistema debe cumplir esta regla verificable: Verificar relación reserva-huésped-alojamiento y estado completado. |
| RN-018 | Reseñas/calificaciones respetan moderación administrativa. | El sistema debe cumplir esta regla verificable: Una reseña puede ocultarse conforme a política; conservar rastro de moderación. |
| RN-019 | Los reportes corresponden a información existente y auditan solicitante/fecha. | El sistema debe cumplir esta regla verificable: Registrar parámetros básicos del reporte y resultado. |

## 4.4 Fuera de alcance de Entrega 1 — WON'T

- **WON'T en esta entrega:** procesar pagos reales o usar credenciales de producción. El flujo de reserva usa únicamente la simulación con proveedor de pruebas indicada en RF-012/RN-016.
- Esta exclusión no es un RF entregable ni una función implementada; documenta un límite explícito del alcance académico.
